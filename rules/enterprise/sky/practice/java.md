## 业务取值承载规范

**核心原则**：类型、状态、查询方式等会进接口、会分支、会有文案的业务取值，必须复用项目已有枚举；没有才新增枚举。禁止在 Service、Helper 里再写一套 `private static final int`。

**适用场景**：sky Java 项目新增或修改接口入参、出参、Service 分支，且取值表示业务类型、状态或查询方式。

**硬性红线**：

- 禁止把会进接口、会分支的业务取值写成类内 int 常量。
- 禁止把枚举类型直接写进接口字段。接口继续传 `Integer` 或 `String`。
- 已有枚举值对不上当前分组时，禁止套用残缺枚举，也禁止补一套未确认的值。

**正确做法**：

- 判断侧使用 `XxxEnum.ITEM.getCode().equals(value)`。
- 常量只承载单个类内部、不进接口、不给前端、不参与业务分支的技术值。
- 找不到完整枚举时，保持原集合，并在交付中说明缺口。

```java
// ❌ 禁止 - 查询方式会进接口、会分支，却在类里再写一套常量
private static final int QUERY_TYPE_CODE = 1;

if (Objects.equals(queryType, QUERY_TYPE_CODE)) {
    return queryByCode(keywords);
}

// ✅ 正确 - 接口仍传 Integer，判断侧用枚举
if (XxxQueryTypeEnum.CODE.getCode().equals(queryType)) {
    return queryByCode(keywords);
}
```

**判断标准**：

- 这个值是否会进接口、参与分支或对应文案。会，就用枚举。
- 接口字段是否仍是 `Integer` 或 `String`。
- 复用的枚举是否覆盖当前全部分组。不覆盖，就不能套用。

## 接口文档版本注解规范

**核心原则**：接口入参或出参发生变化时，必须用当前开发版本号标注本次契约。禁止把后续变更继续留在旧分类或旧版本里，导致文档只能看到最初那一版。

**适用场景**：sky Java 项目新增接口，或修改已有接口的请求参数、响应字段、字段类型、字段含义。

**版本来源**：

- 版本号取当前开发分支的 `vx.x.x`。例如分支是 `feature/v4.1136.0`，版本号就是 `v4.1136.0`。
- 分支名对不上、存在多个候选版本，或用户指定了别的版本时，先问用户，禁止自行挑选。

**正确做法**：

- 在发生契约变化的方法上追加版本 tag，沿用项目已有写法：`@ApiOperation(value = "业务名称", tags = "v4.1136.0")`。
- 版本 tag 只写 `vx.x.x`，不写 `vx.x.x_分类`。
- 同一个版本可以标注多个接口，也可以跨不同业务分类。
- 未改入参、出参的方法不补版本 tag。
- 类上的业务分类 tag 保持原分类，不用版本号替换分类名。

```java
// ❌ 禁止 - 入参已变，仍留在旧分类，文档看不到本次版本
@ApiOperation("查询业务列表")

// ✅ 正确 - 当前分支 feature/v4.1136.0，只标本次变化的方法
@ApiOperation(value = "查询业务列表", tags = "v4.1136.0")
```

**判断标准**：

- 本次是否改了入参或出参。没改，不加版本 tag。
- 版本号是否来自当前开发分支，或用户已确认。
- 是否只写 `vx.x.x`，没有拼分类名。
