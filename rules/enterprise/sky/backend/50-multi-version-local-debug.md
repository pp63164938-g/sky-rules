# 多版本开发部署与本地联调规范

> **来源**：sky 企业多版本部署文档，并以当前前端源码核对请求透传链路。归属 `rules/enterprise/sky/backend/`。本文件只约束运行时版本隔离和本地联调接入，不替代发布平台的构建、发布和回收流程。
> **当前事实**：版本标识、四个本地环境变量、页面 `gray` 参数、请求头 `X-Deploy-Version` 和灰度域名入口，已由企业演示文档与前端源码核对。发布平台点击步骤、网关按员工工号分流的内部实现，不在本文件展开。

## 多版本本地联调

**核心原则**：多版本联调连接的是同一版本标识下的运行实例。后端可以在本地带上该标识启动，前端把同一标识透传过去，不要求先等共享环境构建完成。

**适用场景**：同一业务版本的前端、网关或业务服务需要同时验证，且共享环境尚未发布该版本。只启动单个服务、不需要版本隔离时，不使用本规则。

**约束对象**：版本标识、本地进程环境变量、页面版本参数、请求头透传和本次运行产物。不约束发布平台如何构建镜像，也不约束普通接口字段。

**硬性红线**：

- 禁止把开发版本号、迭代分支名、登录页版本参数、请求头和灰度域名入口写成可以互相替代的四套值。
- 禁止从分支名猜测新的转换规则。只有 `feature/vX.Y.Z` 这一已确认格式，才按历史口径把 `/` 和 `.` 换成 `-`。
- 禁止把灰度域名自动写入的 `latest` 当成某一次迭代的版本标识。
- 禁止为了连接本地实例，修改业务请求文件、写死请求头、改提交参数或改默认环境配置。
- 禁止脑补本地地址、端口、启动类或未在当前项目源码中出现的透传字段。

**版本标识**：

- 已确认格式：迭代分支 `feature/vX.Y.Z` 对应版本标识 `feature-vX-Y-Z`。例如 `feature/v3.119.5` 对应 `feature-v3-119-5`。
- 该标识同时用于页面 `gray` 参数、请求头 `X-Deploy-Version` 和后端 `DEPLOY_VERSION`。
- 分支不符合该格式、文档给出另一标识，或用户明确指定另一标识时，先确认，不套用转换。

**后端本地实例**：

- 通过环境变量声明版本，不改业务代码。四个变量为 `DEPLOY_TIME`、`DEPLOY_ENV`、`DEPLOY_TYPE=gray`、`DEPLOY_VERSION=<已确认版本标识>`。
- `DEPLOY_TIME` 取本次启动时间，`DEPLOY_ENV` 取当前目标环境。这两个值不是版本标识。
- 启动类、端口、JDK 和本地地址从当前项目配置读取。禁止把某次演示里的地址、端口或启动类写成通用值。

**前端透传**：

- 当前前端源码的链路是：路由 query `gray` 写入本地存储 `gray`；请求拦截器在该值非空时设置请求头 `X-Deploy-Version`。上传请求走同一请求实例时，不另写一套透传。
- 本地联调优先直接写入本次运行的本地存储，或通过带 `gray` 的入口访问。禁止把版本标识写死在请求工具的默认请求头里。
- 域名包含 `gray` 且地址没有显式 `gray` 时，当前源码会写入 `latest`。这只表示最近发布的灰度入口，不表示本次迭代标识。
- 页面可以展示当前版本标识；清空该本地值后，请求不再携带版本头。清空动作只影响本次浏览器存储，不改变后端实例。

**事实失效**：

- 环境变量名、query 名、本地存储名或请求头名在企业文档或当前前端源码中变化时，以新事实为准，停止套用本文件旧字段。
- 当前源码与企业文档不一致时，透传链路以当前前端源码为准，并在交付中说明差异。禁止在业务代码里同时兼容两套未确认字段。

**判断标准**：

- 前端请求头、页面入口和后端进程是否使用同一个已确认版本标识。
- 是否没有修改业务代码来伪造这条链路。
- 是否没有把 `latest`、开发版本号原文或未确认的连字符格式混成同一标识。
- 本地环境变量、IDE 启动参数和浏览器本地存储是否都按本次运行产物处理，默认不提交。
