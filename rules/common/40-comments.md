# 代码清理规范

修改代码时同步清理废弃资源：

1. **替换 i18n 翻译 key 时**：同时删除被替换的旧 key
2. **删除/修改组件引用时**：检查被引用的资源（翻译、图标、样式）是否还有其他地方使用，没有则删除
3. **修改完成后**：使用搜索工具确认旧代码/翻译确实无引用

**目的**：避免遗留无用代码和翻译，保持代码库整洁。

# 注释规范

**注释内容边界**：

- 代码注释只服务后续维护者理解业务含义、数据来源和分支原因，并且只描述当前代码需要长期维持的业务事实；禁止记录任务执行过程。
- 禁止将 AI 与用户的交流留痕写进业务代码，包括“用户已确认”“按本轮沟通”“参考本次截图”“查证后发现组件默认支持”“为了遵守规则”等过程性说明。
- 需求澄清、用户确认、方案取舍、组件 / Hook 默认能力查证和代码审查结论，应记录在对话、需求决策台账、方案文档或交付说明中。如果沟通结论形成代码无法自行表达、且需要长期维护的业务约束，必须改写成不包含沟通过程的业务事实后再添加注释。
- 如果组件类型、Prop、校验规则、变量命名或代码结构已经完整表达约束，禁止为了证明 AI 已理解、已查证或已执行而重复添加注释。
- 禁止写“禁止使用 xxx”“按规则 xxx”“避免违反 xxx”这类给 AI 自己看的规则执行说明。
- 禁止把本次排错、复盘、审查提醒、工具判断过程写成代码注释；这些内容应放在对话回复、方案文档或规则复盘中。
- 禁止用注释替代最终回复中的发散点、待确认项或兜底说明；代码注释和用户交付说明是两件事。
- 禁止把本次改动交代、字段收口说明、方案取舍过程写进代码注释。例如“统一使用同一接口字段”“已确认业务类型都走该字段”“兼容新旧字段后收口”“按审查意见调整”。这些是给用户的交付说明，只能写在对话回复里。
- 判断标准：不看本次对话，只看注释，能否把它理解成当前代码需要长期维持的业务事实；如果只能理解成“这次为什么这么改”，就必须删除，或改写成不包含改动过程的业务事实。
- 字段归并、函数抽取、Options 复用等代码结构变化，禁止再用注释复述改动过程。代码能看出来的，注释不要再讲一遍。
- **正式注释与临时预留说明必须分离**：JSDoc、字段说明、函数说明、模板业务注释等正式注释只说明稳定业务含义，例如“业务字段”“操作入口”“数据结构”。待联调原因、后端缺口、临时值来源、联调时删除 / 替换范围等临时说明，必须放在 `@todo-start` / `@mock-start` 标记行、独立 TODO 字段名或最终交付说明中。禁止把 `TODO待联调_` / `TODO无此联调字段_`、“最终以后端为准”、“待后端确认”等内容混进正式 JSDoc，导致联调时还要判断正式注释是否需要修改。
- 注释应写业务事实，例如接口字段来源、业务分支含义、特殊兜底原因。

```ts
// ❌ 禁止 - 向用户交代本次字段收口
/** 已确认业务类型统一使用详情字段 xxx */

// ✅ 正确 - 只说明长期业务事实
/** 详情 xxx，来自接口字段 xxx */
```

```ts
// ❌ 禁止 - 共用同一结果时，注释写成改动说明
// 人工处理、自动处理、定时处理（mode = 1、2、3）：统一使用同一接口字段。

// ✅ 正确 - 共用同一结果时，只写业务结果
// 人工处理、自动处理、定时处理（mode = 1、2、3）：展示业务字段。
```

示例：

```javascript
/** 绑定赠送金额 */
giftAmount: ''

/** 获取绑定赠送金额 */
async fetchGiftAmount() {
    // 先校验参数
    if (!this.userId) return

    /** 接口响应数据 */
    const res = await api.getGiftAmount()
    this.giftAmount = res.data
}
```

```javascript
// ❌ 禁止 - 把规则提醒写进业务代码
// 使用 code 判断，禁止用 name 文案做业务判断
return optionItem.value === TARGET_SCENE_CODE

// ✅ 正确 - 只说明当前业务事实
// 目标场景：接口 code = TARGET_SCENE_CODE
return optionItem.value === TARGET_SCENE_CODE
```

## 非需求文档口径必须可找回

**核心原则**：代码里多出来的交互，以及会改变操作结果的逻辑，如果需求文档里没有这条，注释必须让后来的人打开真实来源、一次定位到原文。只写结论，等于把出处弄丢。接口路径、字段、枚举值和已确认的值映射不套本段。

**适用场景**：交互或逻辑已经写进代码，但依据不在需求文档，而在接口文档、对接说明、原型或其他资料。需求文档已经写了这条时，按普通业务注释写，不套本段。

**套本段**：

- 交互：展示、隐藏、禁用、清空、忽略、二次确认，以及入口是否进入页面。
- 逻辑：提前返回、提交前丢掉字段、按类型改走另一套操作，以及接口建议改成的页面行为。需求文档没有时，即使依据在接口文档，也套本段。

**不套本段**：

- 接口路径、请求字段、响应字段、字段类型、枚举值、提交结构，按接口文档写。需求文档通常不写这些。注释只说明字段含义和必要差异，不写文件名、搜索串，也不写「需求文档无此条」。
- 两套已确认编码之间的值映射，一行写清差异即可。例如「提交字段传接口值，不是页面选项值」。
- 不得因为写在字段赋值旁边，就把禁用、清空、忽略、提前返回当成字段注释。

「按本段留出处」只约束上面「套本段」的交互和逻辑。字段和值映射按「不套本段」写。

**不授权新行为**：本段只约束出处怎么留。接口文档有、需求文档没有时，能不能写进代码，仍按需求与接口优先级、冲突沟通和业务推导规则判断。禁止借本段把接口建议直接写成确定逻辑。

**硬性红线**：

- 禁止只写「见接口文档」「按对接说明」或章节标题。章节标题不能当搜索串。
- 禁止编造链接。没有稳定链接就写「无稳定链接」。
- 禁止把出处只留在提交说明、对话或回复里。注释写在实现该行为的代码旁。
- 禁止在注释里摘整段原文、写版本哈希或沟通过程。原文会改，注释会过期。回复里的引用仍按「来源引用可复核规范」摘原文。
- 未读需求文档时，禁止写「需求文档无此条」。

**套本段时，注释至少包含**：

1. 行为本身，以及资料给出的处理建议，不要只写章节名。
2. 可打开的位置：文件写完整文件名；链接写 URL。没有稳定链接要写明。
3. 能在该文件或该页唯一命中原文的搜索串，必须照抄原文，不能改写。不唯一时补所在章节。
4. 需求文档确无此条时，写明「需求文档无此条」。

同一口径多处实现时，每处用能命中该处对应原文的搜索串。找回步骤写在实现处，不在每个调用点复制。

**写不出唯一搜索串时**：停下来问，不要写模糊注释。

**触发可见性**：套本段时，开发前说明这次是交互或逻辑、必须留出处。不套本段时，说明这次是字段或值映射、按字段注释写。落地出处注释后，交付说明里点明「需求文档无此条，出处在注释里」。

```javascript
// ❌ 禁止 - 需求文档没有这条，注释只有结论
/** 选中业务名称后，类型与归属不再参与筛选 */

// ✅ 正确 - 全名 + 照抄的搜索串，后来能直接定位
/**
 * 选中业务名称后，类型与归属不再参与筛选。需求文档无此条。
 * 来源文件：<版本>-<对接说明全名>.md（本机下载，无稳定链接）。
 * Ctrl+F「传了业务标识时忽略类型与归属」。
 * 建议：选中后禁用或清空这两个条件。
 */
```

链接来源同样写 URL、打开后的位置和唯一搜索串。

```javascript
// ❌ 禁止 - 接口枚举映射，却按出处四件套写
// 目标类型提交值为 2，不是页面选项 9。需求文档无此条。
// 来源文件：<对接说明全名>.md（本机下载，无稳定链接）。
// Ctrl+F「目标类型传 2」。
params.type = form.type === PAGE_TYPE ? 2 : form.type

// ✅ 正确 - 只说明两套值的差异
// 目标类型提交值为 2，不是页面选项 9
params.type = form.type === PAGE_TYPE ? 2 : form.type
```

# 文件头部注释规范

**核心原则**：所有代码文件顶部需添加功能描述注释，说明该文件是哪个页面或功能。

**格式要求**：

| 文件类型   | 注释格式            | 示例                         |
| ---------- | ------------------- | ---------------------------- |
| .vue       | `<!-- 功能描述 -->` | `<!-- 提现/充值抽屉组件 -->` |
| .js/.ts    | `/** 功能描述 */`   | `/** 公共接口定义 */`        |
| .jsx/.tsx  | `/** 功能描述 */`   | `/** 用户列表页面 */`        |
| .scss/.css | `/* 功能描述 */`    | `/* 全局公共样式 */`         |

**注意事项**：

- 注释放在文件最顶部（第一行）
- 描述应简洁明了，说明文件的用途或所属功能模块
- 不要放文件路径，而是描述功能
