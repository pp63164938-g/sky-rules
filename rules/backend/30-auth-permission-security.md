# 后端鉴权权限与安全边界规范

**核心原则**：安全边界必须由服务端强制执行，前端显隐和按钮禁用只能提升体验，不能作为权限、数据隔离或敏感操作的依据。

**适用场景**：鉴权中间件、权限点、租户 / 组织 / 用户数据隔离、资源归属校验、敏感字段、Token、回调接口、上传下载和开放 API。

**硬性红线**：

- 禁止只依赖前端路由、按钮权限或菜单资源控制后端访问。
- 禁止缺少资源归属校验，例如用户能通过 ID 访问其他租户、组织或账号的数据。
- 禁止在日志、错误信息、响应体或测试数据中输出 Token、密钥、密码、验证码、身份证件、银行卡等敏感信息。
- 禁止把客户端传入的用户 ID、租户 ID、角色、权限标识直接作为可信身份。
- 禁止为了联调临时关闭鉴权、签名、权限或限流后不做显性标记和恢复计划。

**正确做法**：

- 身份信息从服务端会话、Token 解析结果或可信网关注入中获取，不从普通请求参数信任。
- 每个读写接口都应校验资源归属和操作权限；批量接口必须逐项或按可信集合校验。
- 敏感字段默认不返回；确需返回时必须脱敏、最小化，并说明调用场景。
- 外部回调、开放接口和上传下载必须校验签名、来源、文件类型、大小、路径和重放风险。
- 临时放宽安全限制必须有可搜索标记、影响范围说明和清理条件。

**代码示例**：

```ts
// ❌ 禁止 - 信任客户端传入的租户 ID
const tenantId = request.body.tenantId

// ✅ 正确 - 从可信身份上下文获取租户
const tenantId = authContext.tenantId
await permissionService.assertCanRead({ tenantId, resourceId })
```

**判断标准**：

- 删除前端权限控制后，后端是否仍能阻止越权操作。
- 修改请求参数中的用户、租户、角色或资源 ID 是否无法越权。
- 日志和错误返回是否不包含敏感信息。
- 临时安全降级是否可搜索、可清理、可追踪。
