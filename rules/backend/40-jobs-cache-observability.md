# 后端任务缓存与可观测性规范

**核心原则**：后台任务、缓存和异步流程必须具备可重试、可观测、可恢复的边界，禁止失败后静默吞噬或让数据状态不可解释。

**适用场景**：定时任务、队列消费者、消息回调、缓存、分布式锁、重试补偿、日志、指标、告警、后台轮询和第三方系统对接。

**硬性红线**：

- 禁止后台任务失败只 `console.error` 或记录本地日志，不更新任务状态、不告警、不暴露给运维入口。
- 禁止没有幂等键、锁或去重机制的任务在重试后重复写入核心业务数据。
- 禁止缓存键无命名空间、无过期策略、无失效路径，导致跨租户污染或长期脏读。
- 禁止消息消费先确认成功再执行关键业务写入，导致失败后无法补偿。
- 禁止无限重试、无限轮询或无超时调用第三方系统。

**正确做法**：

- 后台任务应记录开始、成功、失败、重试、跳过等明确状态，并保留可定位的业务 ID。
- 重试任务必须设计幂等键；并发任务应使用锁、唯一约束或状态机防止重复处理。
- 缓存 key 必须包含业务域、租户 / 用户隔离维度和版本语义；写入路径必须同步设计失效策略。
- 第三方调用必须设置连接超时、总超时和失败终态；无法自动恢复时触发告警或人工处理状态。
- 日志应包含 requestId / traceId / jobId 等关联字段，避免只留下不可搜索的自然语言。

**代码示例**：

```ts
// ❌ 禁止 - 任务失败只打印，外部无法感知
try {
    await syncXxx()
} catch (error) {
    console.error(error)
}

// ✅ 正确 - 失败进入可观测终态
try {
    await syncXxx()
    await jobRepository.markSuccess(jobId)
} catch (error) {
    await jobRepository.markFailed(jobId, getSafeErrorMessage(error))
    await notifyOwner({ jobId, status: 'failed' })
}
```

**判断标准**：

- 任务失败后用户、运维或开发是否能看到明确终态。
- 同一消息或任务重复执行是否不会造成重复业务结果。
- 缓存是否能解释来源、隔离维度、过期和失效路径。
- 第三方依赖异常时是否有超时、降级、告警或人工处理路径。
