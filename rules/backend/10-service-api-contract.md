# 后端接口契约与服务分层规范

**核心原则**：后端接口实现必须以已确认的数据契约为准，服务端承担真实校验、权限和业务一致性，禁止为了配合前端页面临时拼接口或放宽约束。

**适用场景**：新增或修改 Controller、Router、Service、DTO、请求响应结构、错误码、分页排序、导入导出、批量操作等后端接口能力。

**硬性红线**：

- 禁止凭前端字段名、页面文案或历史相似接口脑补请求参数、响应字段、枚举值或错误码。
- 禁止只在前端做必填、枚举、权限或金额校验；服务端必须重新校验。
- 禁止 Controller / Router 里堆业务规则、数据库拼装和复杂状态流转；应下沉到明确的 Service / Domain 层。
- 禁止直接返回 ORM 实体、数据库原始字段或包含敏感信息的内部对象。
- 禁止把未确认的兼容字段静默写入响应；必须标记待确认或先补充接口契约。

**正确做法**：

- 接口路径、方法、Query、Body、响应结构和错误码必须来自接口文档、OpenAPI、需求确认、抓包或后端负责人确认。
- 入参用 DTO / Schema / 类型定义表达真实契约；字段含义、可选语义和枚举值应贴近定义处说明。
- Controller / Router 只做协议适配、鉴权入口、参数绑定和响应包装；业务判断由 Service / Domain 层承载。
- 响应对象应显式组装，只暴露前端或调用方需要的字段。
- 接口变更涉及兼容旧客户端时，必须说明版本策略、兼容字段和移除条件。

**代码示例**：

```ts
// ❌ 禁止 - 直接透出数据库实体，字段和敏感信息边界不可控
return repository.findMany(query)

// ✅ 正确 - 显式组装接口响应字段
const recordList = await service.getXxxList(queryDto)
return recordList.map(recordItem => ({
    id: recordItem.id,
    name: recordItem.name,
    status: recordItem.status
}))
```

**判断标准**：

- 接口字段、枚举和错误码是否都有明确来源。
- 服务端是否独立完成关键校验，而不是依赖前端拦截。
- 调用方是否只能看到契约字段，看不到内部实现细节。
- 新增接口是否能从文档、类型和测试中还原真实入参和响应。
