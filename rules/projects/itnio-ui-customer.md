# itnio-ui-customer 项目专用规范

## 错误码（errorCode）扩展规范

**核心原则**：新增错误码时，**必须与同模块已有的错误码集中放置**，禁止直接追加到文件末尾。

**操作步骤**：

1. **先搜索已有错误码**：新增前先在 `errorCode.js` 中搜索同前缀/同模块的已有 code（如 `37510` 开头的放一起，`400` 开头的放一起）
2. **集中放置**：将新 code 插入到同模块已有 code 的下方，而非文件末尾
3. **cn 和 en 同步**：cn 部分和 en 部分都要在对应位置集中放置

**反面案例**：

```javascript
// ❌ 禁止 - 37510010/11/12 在文件中间，37510013 却放到文件末尾
37510010: "代理商不存在",  // L167
37510011: "已绑定代理商",  // L168
// ... 中间隔了 300 行 ...
37510013: "该推荐星推官...",  // L490（文件末尾）

// ✅ 正确 - 同前缀集中放置
37510010: "代理商不存在",
37510011: "已绑定代理商",
37510012: "该账号不可绑定代理商",
37510013: "该推荐星推官尚未成为正式推广星推官，暂无法接受绑定!",
```

## 错误提示（$notice）规范

**核心原则**：接口错误提示**必须使用 `this.$notice.error(err.code)`**，禁止直接使用后端返回的 `err.msg`。

**目的**：`$notice.error(code)` 内部会自动根据 code 查找 `errorCode` 的 i18n 翻译，确保多语言正确显示。

**代码示例**：

```javascript
// ❌ 禁止 - 直接用后端返回的 msg（永远显示中文，不走 i18n）
} catch (err) {
    this.$notice.error({ title: err.msg || err.message || 'error' })
}

// ✅ 正确 - 传 code，由 $notice 内部处理 i18n 翻译
} catch (err) {
    this.$notice.error(err.code)
}
```

**参考文件**：`src/layout/common/itnio-workspace.vue` 中的 `this.$notice.error(e.code)`

## 扩展前确认规范

**核心原则**：修改 i18n / errorCode 等公共文件前，**必须先确认当前文件的实际内容**，避免重复添加。

**操作步骤**：

1. **先搜索确认**：用 grep 搜索要添加的内容是否已存在
2. **查看上下文**：查看目标插入位置的前后 5-10 行，确认上下文正确
3. **禁止凭记忆操作**：即使之前的对话中讨论过某内容"不存在"，也必须重新搜索确认
