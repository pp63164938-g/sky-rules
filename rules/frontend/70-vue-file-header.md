# 前端 Vue 注释规范

## Vue 组件业务说明注释规范

**适用场景**：Vue 模板结构、业务组件、函数 / 变量 / 类型、条件分支、兜底值、数据转换、复杂 Map / Record / 缓存结构、样式块。

**硬性红线**：注释必须贴近代码并说明业务含义或分支原因；禁止空泛注释、远离代码的规则堆叠、无注释堆复杂结构。

- **格式**：在组件最外层节点内部（如 `<template>` 开头处）或 `export default` 上方，必须添加明确的中文业务名称或功能说明注释。
- **目的**：保持极高的可读性，让接手人员无需阅读内部实现细节，也能快速明确该组件的业务用途。
- **代码示例**：
  ```vue
  <template>
    <!-- 预约活动报名提醒弹窗 -->
    <WcDialog :visible="visible"></WcDialog>
  </template>
  ```
  或
  ```javascript
  /**
   * 预约报名弹窗
   * 业务场景：点击 Hero 横幅区的“立即预约”时弹出
   */
  export default { ... }
  ```

## Vue 文件头部注释规范

**核心原则**：所有新创建的 Vue 组件文件（包括业务组件、公共基础组件等），**必须在文件头部（`<template>` 的第一行）添加清晰的业务语义说明注释。**

**目的**：让后续接手人员或 AI 在打开文件时，能第一眼明确该组件的“业务身份”、核心设计规范以及适用场景，杜绝“不知其所以然”的幽灵组件。

**顶部注释表达规则**：

- 单行顶部注释优先使用“业务对象：职责 / 场景”的短句结构，让读者第一眼区分所属业务和文件职责。
- 普通页面、弹窗、页面专属业务子组件，优先使用一行注释；只有公共基础组件、设计规范较强或跨场景复用组件，才使用多行注释补充使用场景。
- 禁止把多个业务名词直接串成一长句，例如“业务对象关联对象处理方案展示”；应使用冒号、空格或短横线分层，其中冒号优先。
- 顶部注释只说明文件业务身份和职责，不写实现细节、联调缺口、字段来源或本次修改原因。

**顶部注释表达示例**：

```vue
<!-- ❌ 不推荐 - 多个名词直接串联，读者需要自行断句 -->
<!-- 业务对象关联对象处理方案展示 -->

<!-- ✅ 推荐 - 用“业务对象：职责”分层 -->
<!-- 业务对象：关联对象处理方案 -->

<!-- ✅ 推荐 - 页面专属子组件可补充组件身份 -->
<!-- 业务对象：关联对象处理方案组件 -->
```

**代码示例**：

```vue
<!-- ❌ 禁止 - 没有任何说明直接开始写模板 -->
<template>
  <button class="wc-btn">
    <slot></slot>
  </button>
</template>

<!-- ✅ 推荐 - 在文件顶部清晰标注组件身份与用途 -->
<!--
  文件说明：世界杯活动页 - 专属公共基础按钮组件
  设计规范：严格还原 Figma 设计稿中的实心主按钮、空心次按钮及成功状态
  使用场景：预约弹窗、竞猜弹窗等所有需要标准按钮的地方
-->
<template>
  <button class="wc-btn">
    <slot></slot>
  </button>
</template>
```

**判断标准**：

- 新建任何 `.vue` 文件时，绝对禁止不加说明直接裸写代码。
- 头部注释必须至少包含：**文件/组件说明**（这是干嘛的）和 **使用场景**（在哪些地方调用）。

## HTML/Vue 模板注释规范

**核心原则**：对于复杂的组件结构（如卡片、列表项、左右布局容器等），**必须为关键的 HTML 节点添加包裹式或起手式注释**，以清晰标明业务含义，与 CSS 样式全覆盖注释相呼应。

**强制要求**：

- 严禁在没有任何注释的情况下连续堆砌大量的 `<div>` 等无语义标签。
- 注释必须说明“这是什么业务模块”（例如：`<!-- 战绩详情数据列 -->`、`<!-- 头部左侧：汇总场次与日期 -->`）。
- 尤其是使用了 Flex/Grid 布局的大型结构骨架，其主要父容器必须拥有明确的业务说明注释。
- 当页面 / 弹窗已经拆成多个页面专属业务子组件后，主入口模板仍必须为关键子组件和布局容器添加起手式注释，说明该子组件承载的业务区块。
- 子组件名不能完全替代业务注释；禁止主入口只连续堆叠多个 `<Xxx />`，让读者必须逐个打开子组件才能理解页面结构。
- 注释粒度以业务区块和布局骨架为单位，例如头部、主内容、侧边栏、底部操作、左侧配置区、右侧预览区；不要给普通字段、普通按钮、单个简单组件机械补注释。
- 如果子组件名称已经非常清楚，注释应补充“位置 + 业务职责”，不要重复组件名本身。

**目的**：提高模板的结构可读性，防漏、防错，方便接手人员能够做到“仅看模板注释就能秒懂业务布局结构”。

**代码示例**：

```vue
<!-- ❌ 禁止 - 无任何结构说明，纯标签堆砌 -->
<div class="wc-history-card__inner">
    <div class="wc-history-card__teams">
        <img src="xxx" />
        <span>巴西</span>
    </div>
</div>

<!-- ✅ 推荐 - 具备结构化的业务说明注释 -->
<div class="wc-history-card__inner">
    <!-- 球队对阵信息：左右国家队国旗及名称 -->
    <div class="wc-history-card__teams">
        <img src="xxx" />
        <span>巴西</span>
    </div>
</div>
```

**页面组合入口示例**：

```vue
<!-- ❌ 禁止 - 拆分后主入口缺少业务结构说明 -->
<XxxHeader />
<div class="xxx-layout">
    <XxxMain />
    <XxxAside />
</div>

<!-- ✅ 正确 - 主入口能直接看出页面结构 -->
<!-- 详情头部：基础信息、核心指标和顶部操作 -->
<XxxHeader />

<!-- 详情内容：左侧业务内容与右侧辅助信息 -->
<div class="xxx-layout">
    <!-- 详情主内容：业务说明和数据概览 -->
    <XxxMain />

    <!-- 详情侧边栏：附件和关联对象 -->
    <XxxAside />
</div>
```
