# Vue 组件与文件头部注释规范

**核心原则**：所有新创建的 Vue 组件文件（包括业务组件、公共基础组件等），**必须在文件头部（`<template>` 的第一行）添加清晰的业务语义说明注释。**

**目的**：让后续接手人员或 AI 在打开文件时，能第一眼明确该组件的“业务身份”、核心设计规范以及适用场景，杜绝“不知其所以然”的幽灵组件。

**顶部注释表达规则**：

- 单行顶部注释优先使用“业务对象：职责 / 场景”的短句结构，让读者第一眼区分所属业务和文件职责。
- 普通页面、弹窗、页面专属业务子组件，优先使用一行注释；只有公共基础组件、设计规范较强或跨场景复用组件，才使用多行注释补充使用场景。
- 禁止把多个业务名词直接串成一长句，例如“业务对象关联对象处理方案展示”；应使用冒号、空格或短横线分层，其中冒号优先。
- 顶部注释只说明文件业务身份和职责，不写实现细节、联调缺口、字段来源或本次修改原因。

**顶部注释表达示例**：

```vue
<!-- ❌ 不推荐 - 多个名词直接串联，读者需要自行断句 -->
<!-- 业务对象关联对象处理方案展示 -->

<!-- ✅ 推荐 - 用“业务对象：职责”分层 -->
<!-- 业务对象：关联对象处理方案 -->

<!-- ✅ 推荐 - 页面专属子组件可补充组件身份 -->
<!-- 业务对象：关联对象处理方案组件 -->
```

**代码示例**：

```vue
<!-- ❌ 禁止 - 没有任何说明直接开始写模板 -->
<template>
  <button class="wc-btn">
    <slot></slot>
  </button>
</template>

<!-- ✅ 推荐 - 在文件顶部清晰标注组件身份与用途 -->
<!--
  文件说明：世界杯活动页 - 专属公共基础按钮组件
  设计规范：严格还原 Figma 设计稿中的实心主按钮、空心次按钮及成功状态
  使用场景：预约弹窗、竞猜弹窗等所有需要标准按钮的地方
-->
<template>
  <button class="wc-btn">
    <slot></slot>
  </button>
</template>
```

**判断标准**：

- 新建任何 `.vue` 文件时，绝对禁止不加说明直接裸写代码。
- 头部注释必须至少包含：**文件/组件说明**（这是干嘛的）和 **使用场景**（在哪些地方调用）。
