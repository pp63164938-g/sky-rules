# 项目上下文定位

## 文件关系

- `base.project-context.md`：工作流源文件，说明如何定位目录文件、识别项目和执行项目专属要求；同步到 Codex 后对应 `base-project-context` Skill。
- `project-catalog.json`：项目目录数据文件，记录项目识别信息、单一文档来源和项目专属要求。
- 两者组成不可拆分的工作流资源包：前者描述“怎么做”，后者保存“有哪些项目和目录”。同步到任何平台时，目录文件必须与当前平台的 `base-project-context` 工作流或 Skill 放在同一目录，并保持与源文件内容完全一致。

**多平台一致性**：`project-catalog.json` 只有仓库根目录一份源文件。同步脚本负责把它作为伴随资源分发到所有启用的工作流平台；任一平台缺失或内容不一致时，同步必须失败，禁止只报告工作流文件同步成功。

**一来源一条目**：`projects` 中的每条目录记录只对应一个文档来源。测试 / 开发等不同环境、不同 Git 仓库或不同网页文档必须拆成独立条目，禁止自行增加 `documents` 数组把多个来源嵌套在同一条记录中。

**固定模板字段**：每条目录记录只允许使用 `project`、`description`、`match`、`docs`、`rules`。扩展目录时只能按该模板新增独立条目，禁止自行增加其他字段或改用另一套嵌套结构；确需调整模板时必须先预览并取得用户确认。

## 目录文件格式

```json
{
  "projects": [
    {
      "project": "xxx-requirement-docs",
      "description": "XXX 需求文档仓库",
      "match": ["xxx项目", "需求文档"],
      "docs": "xxx_pm",
      "rules": [
        "读取需求前先获取文档仓库 origin/main 最新内容。",
        "根据开发分支、页面路径和关键词匹配需求版本；存在多个候选时让用户确认。"
      ]
    },
    {
      "project": "xxx-test-api-docs",
      "description": "XXX 测试环境接口文档",
      "match": ["xxx项目", "测试环境"],
      "docs": "https://docs.example.com/api",
      "rules": [
        "该文档是无需登录的网页接口文档，可以直接解析。"
      ]
    }
  ]
}
```

字段作用：

- `project`：目录记录唯一名称，同时默认用于匹配项目文件夹名称或文档来源名称。
- `description`：项目用途说明，帮助 AI 理解项目身份。
- `match`：可选的项目别名、特征路径或任务关键词；命中任意一项时作为候选项目。
- `docs`：单一文档来源。可以是相对于 `project-catalog.json` 的目录、由 `rules` 明确为 Git 仓库的仓库目录标识，或 `https://` 网页文档 URL；禁止保存某台电脑的绝对路径。
- `rules`：可选的项目专属要求，只对当前匹配项目生效。

每条记录必须完整包含 `project`、`description`、`match`、`docs` 和 `rules`。共享目录文件禁止保存某台电脑的绝对路径。

## 执行步骤

1. **确定当前项目线索**
   - 优先使用用户明确提供的页面文件、项目目录、项目名称或任务关键词。
   - 用户未明确提供时，再使用当前工作区路径。
   - Git 仅作为可选线索；普通文件夹项目同样可以识别。

2. **定位目录文件**
   - 用户提供了 `project-catalog.json` 路径时，直接读取并验证。
   - 否则先检查当前项目目录及其父目录。
   - 当前项目及父目录未找到时，读取当前已加载的 `base-project-context` 工作流文件或 Skill 文件同目录下的 `project-catalog.json`。该规则不依赖平台名称或固定用户目录。
   - 工作流伴随资源仍未找到时，检查已确认的 `sky-rules` 源仓库根目录；源仓库位置必须按可验证来源定位，禁止写死某台电脑的绝对路径。
   - 仍未找到时，优先限制在当前项目所在磁盘或挂载点的常见项目目录中查找；禁止跨磁盘或全系统无边界扫描。
   - 未找到时明确说明。只有任务依赖外部文档或项目专属要求时才询问目录文件位置；普通任务继续按通用规则处理。

3. **识别项目**
   - 使用 `project` 匹配项目文件夹名称，并使用 `match` 补充匹配项目别名、路径片段和用户当前任务描述。
   - 只有一个候选项目时使用该项目配置。
   - 多个项目同时匹配时列出候选并让用户确认，禁止自行选择。
   - 没有项目匹配时说明当前项目未配置，继续按通用规则处理。

4. **解析文档来源**
   - `docs` 是 `https://` URL 时，按网页文档读取；是否需要登录只以当前目录记录的 `rules` 或用户明确说明为准，无法访问、内容为空或被权限拦截时必须反馈真实结果。
   - `docs` 是相对目录，且读取的是当前项目或 `sky-rules` 源仓库中的目录文件时，先相对于 `project-catalog.json` 所在目录解析，并验证目录是否存在、是否可访问。
   - 读取的是平台同步后的伴随目录文件时，禁止把 `docs` 相对值拼接到平台配置目录；应把它作为项目目录或 Git 仓库标识，按当前项目所在磁盘或挂载点的常见项目目录定位。
   - 相对目录不存在且 `rules` 明确该来源为 Git 仓库时，只在当前项目所在磁盘或挂载点的常见项目目录内，按目录名或 `origin` 远端仓库名定位；只有一个候选时使用，多个候选时让用户确认，未找到时询问仓库位置。
   - 禁止跨磁盘或全系统扫描 Git 仓库，禁止把当前电脑解析出的绝对路径回写到共享目录文件。

5. **执行项目专属要求**
   - 只执行当前匹配项目的 `rules`，禁止继承其他项目的要求。
   - 只有 `rules` 明确要求更新 Git 文档仓库时，才获取对应远端分支；不得把“读取前更新 `main`”扩大为所有项目的通用要求。
   - `rules` 明确要求读取前更新 `main` 时，执行 `git fetch origin main`，并使用 `git ls-tree`、`git show` 等命令从 `origin/main` 快照定位和读取；禁止执行 `git pull`、切换分支或覆盖本地工作区。
   - 多个环境各自配置网页接口文档时，只使用当前命中环境的独立条目；环境无法确认时列出候选让用户选择，禁止默认选择或跨环境借用字段。
   - 非 Git 项目跳过 Git 操作，并继续使用页面路径、项目名称和任务关键词定位资料。
   - 多份需求文档都可能匹配时，必须列出候选并让用户确认。

6. **反馈识别结果**
   - 简要说明目录文件位置、匹配项目、文档目录和本次实际执行的项目专属要求。
   - 未匹配或无法读取时明确说明，不得假装已经加载项目要求。
