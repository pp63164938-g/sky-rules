# 菜单与权限管理自动化技能 (Menu Manage)

本工作流旨在让 AI 完全自动化地向 `skyline-kunlun` 项目插入/修改系统菜单和权限按钮，替代繁琐的页面填表操作。

## 工作流规则与执行步骤

当用户使用 `/kl.menu-manage` 并附带操作指令（如“新增一个菜单”或“添加一个按钮”）时，你（AI）**必须**严格遵循以下执行流程：

### 1. 凭证解析与参数提取
- **获取凭证**：检查对话上下文中是否包含用户从浏览器复制的请求报文（cURL 或 raw HTTP）。从中提取出 `Authorization` Token（通常以 `Bearer ` 开头）以及请求的域名 `BASE_URL`。如果没有发现有效凭证，**必须中断执行**，向用户索要任意一个带有 Token 的请求报文。
- **确认参数**：根据用户的口语描述，提取或推断以下必填字段。如果不明确，需主动向用户确认：
  - `parentRouter` (优先) 或 `parentName`: 父菜单的前端路由路径（例如 `/businessOperations/public/worldcup`）或中文名称（用于去树结构中精准反查 `parentId`）。使用路由定位是最准的！
  - `name`: 即将创建的 菜单/按钮名称
  - `international`: 唯一标识（即权限 Key）。
    **【核心一致性要求】**：此标识必须与前端 Vue 代码中 `useCustomizeField('唯一标识', ...)` 的参数**保持绝对一致**！如果是 Tab 页面，则必须取对应 Tab 的唯一标识，以保证全局唯一。
    **【先确定，再双端同步】**：在执行菜单自动化脚本或修改代码前，**必须先确定好这个唯一的 `international`**。一旦确定，必须将其**同时应用**于后端菜单生成脚本的 `international` 字段，以及前端代码的 `v-sky-authorize` 属性中（一起做这两个事情）。绝不能出现前后端两套标识导致不同步的问题！
    （**注意**：如果是该页面下的导出按钮，必须强制在其父级标识后统一使用 `:export` 作为后缀，如 `...:tab-registration:export`）。
  - `router`: 前端页面路由路径（如果是按钮，可以填写空字符串 `""`）
### 2. 前端代码严格核验 (必须执行)
在提供预览和生成菜单前，**必须主动检查并确保**相关的 Vue 页面代码已经完成对应的权限配置同步：
- **检查权限指令**：确认目标按钮或区块上已经加上了正确的 `v-sky-authorize` 属性，且值与你拟定的标识后缀一致。
- **检查自定义列标识**：全局搜索或检查该页面下的 `useCustomizeField` Hook，确保不存在残留的 `TODO待联调_` 占位符，且其传入的唯一标识参数与父级页面的 `international` 保持绝对一致。
- **展示代码现状**：在最终发给用户的预览内容中，必须包含你检查或修改好的 Vue 代码片段供用户二次核对。

### 3. 前置查树与真实父级完整路径确认 (核心体验，必须执行)
在向用户提供预览前，**你（AI）必须先利用用户的 Token 编写一个查树脚本**，调用后端的 `/v2/sys/staff/resource/query/tree` 接口。
- **递归查找完整路径**：在拿到树结构数据后，必须在脚本中进行递归遍历，找到目标父级节点，并拼装出它的**完整菜单面包屑路径**（如 `运营中心 / 公共 / 世界杯活动管理 / 消费返现记录`）及其真实 ID。
- **必须依赖接口，非依赖页面**：因为用户需要核对按钮最终挂载的系统绝对位置，仅仅给出代码标识是没有业务意义的。
- **强制表单级全字段预览 (双端对齐)**：为了给用户提供最真实、最有安全感的确认体验，**必须完全复刻系统界面的填表项**进行展示。除了父级菜单作为挂载基准放在顶部外，其余所有表单项**必须全部塞进表格列中**（即使每行数据重复也要展示，主打绝对对齐）：
  
  **【父级菜单】** `运营中心 / 公共 / ... / 消费返现记录` (真实 ID: 6511xxxx)
  
  | 菜单名称 | 菜单类型 | 唯一标识 (international) | 菜单路径 (router) | 版本号 | 排序 | 是否显示 | 移动端显示 |
  | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
  | 导出 | 按钮(1) | `oc:xxx:xxx:export` | *(按钮为空)* | `v4.678.0` | 10 | 显示 | 隐藏 |

- **强制停顿 (严禁先斩后奏)**：展示**前端代码片段**和**表格预览**后，你**必须主动询问**用户：“请确认 Vue 代码的权限标识与将要生成的菜单配置是否一致并可以执行？”。**绝对禁止**在用户点头前去提前修改 Vue 代码或执行后端写入脚本！

### 4. 自动生成临时脚本 (Node.js)
在 `.gemini/antigravity/brain/<conversation-id>/scratch/` 目录下（使用绝对路径），利用 `write_to_file` 创建一个名为 `run-menu.js` 的脚本文件。脚本逻辑需包含：
- **第一步：查树取 ID**
  - **✅ 优先使用现成 ID (极速模式 O(1))**：**【核心避坑】**如果你在用户提供的 cURL 或请求报文中发现了 `parentId: xxxx` 的参数，**必须直接提取并使用该 `parentId`** 去调用 `POST {BASE_URL}/v2/sys/staff/resource/query/list` 进行精准操作。**严禁**无视现成参数去拉取包含几千个节点的 `/query/tree` 全量树做暴力遍历，否则会导致脚本执行时间从几秒飙升到几分钟的性能灾难！
  - **⚠️ 按路由找 ID (遍历模式 O(N))**：仅在没有任何 `parentId` 线索时，才发送 `GET {BASE_URL}/v2/sys/staff/resource/query/tree` 获取全量树。
  **【避坑指南/经验总结】**：`/query/tree` 接口**不返回 `router` 字段**。因此，当试图通过 `parentRouter` 查找父节点时，**必须**先递归提取树结构中的所有 `id`，然后分批并发请求 `GET {BASE_URL}/v2/sys/staff/resource/detail?id={id}`，遍历匹配详情里的 `router`，直到找到与 `parentRouter` 完全一致的节点，从而获取精准的 `parentId`。
- **关于删除节点的巨坑 (`/delete` 接口 Hang 死问题)**：
  **【避坑指南/经验总结】**：Kunlun 的 `/v2/sys/staff/resource/delete` 接口存在服务端 Bug。当 Node.js 调用该接口时，**服务端虽然能成功删除数据，但不会正确结束 HTTP 响应**，导致 Node.js 的请求被无限期挂起 (Hang 住) 并死锁。
  **解决方案**：如需在脚本中自动删除菜单，**必须为 HTTP 请求设置极短的超时时间（如 1000ms），并在 catch 中忽略超时报错**，只要发出了请求即认为成功，绝对不能使用 `await fetch` 傻等结果，否则整个自动化流程会彻底卡死。
- **第二步：执行写入**
  构造如下结构（`BodyCreateResource`），并通过 `POST {BASE_URL}/v2/sys/staff/resource/add` 发送：
  ```javascript
  {
      resourceType: "0", // 菜单为 "0"，按钮为 "1"
      name: "XXX",       // 提取的名称
      international: "XXX", 
      parentId: parentId, // 第一步查出来的真实 ID
      router: "XXX",     // 按钮通常为空字符串 ""
      version: "vX.X.X", // 提取的版本号
      sort: 10,          // 默认均写 10，无需刻意递增
      webShowFlag: true,
      appShowFlag: false
  }
  ```

### 5. 静默执行与痕迹清理
1. 脚本创建完成后，使用 `run_command` 工具在终端静默执行该脚本：`node <绝对路径>/run-menu.js`。
2. **分析结果**：
   - 捕获脚本的 `console.log` 返回内容。
   - 如果遇到 `401 Unauthorized`，向用户报告 Token 可能已过期，需重新复制。
   - 如果新增成功，向用户做简短捷报（如：“已成功在「世界杯管理」下新增「积分排名」菜单”）。
3. **清理战场**：
   - 使用 `run_command`（Windows下使用 `Remove-Item -Force <绝对路径>/run-menu.js`）删除临时脚本文件，保持本地目录整洁。

> **警告**：本技能仅限作为接口调用的自动化载体，绝对禁止在此过程中自行发散去修改 Vue 或 TS 业务代码。
