---
description: 根据项目文档规范执行（优先读取 docs 目录；接口问题查询线上接口文档）
---

1. **搜索项目文档**
   - 优先在项目根目录下搜索 `docs` 目录。
   - 使用 `find_by_name` 或 `list_dir` 查找 `docs` 目录下的关键文件（如 `README.md`, `design`, `spec`, `requirements` 等）。
   - **优先级规则**：`docs` 目录 > `openspec` 目录 > 根目录 `README.md`/`api.md`。
   - 如果用户询问接口路径、接口参数、请求字段、响应字段、接口含义等接口文档问题，优先查询线上接口文档站点。

2. **查询线上接口文档**
   - 当前已知接口文档入口：
     - dev 环境：`https://gw-kunlun.tyhdev.com/doc.html#/home`
     - test 环境：`https://gw-kunlun.tyhtest.com/doc.html#/home`
   - 用户明确指定环境或文档地址时，优先使用用户指定来源。
   - 用户未指定环境时，优先查询 dev 文档，再查询 test 文档。
   - 查询接口时必须核对接口名称、请求方法、URL、Query 参数、Body 参数、响应字段和字段含义。
   - 如果 dev 与 test 文档内容不一致，必须列出差异，并询问用户以哪个环境为准。
   - 如果文档站点不可访问、需要登录、返回 403 或网络受限，必须明确告知用户，并要求用户提供可访问环境、截图、接口文档内容或抓包信息。
   - 如果文档中没有找到对应接口或字段，必须说明“文档未找到”，禁止自行发散补字段、补参数或补接口路径。

3. **读取相关文档**
   - 根据用户的具体请求（FEATURE, BUG, QUESTION），选择性读取最相关的文档。
     - 例如：如果是 UI 任务，优先读取 `docs/spec/web` 或 `docs/design`。
     - 例如：如果是后端任务，优先读取 `docs/spec/server` 或 `docs/api`。
     - 例如：如果是接口联调任务，优先读取线上接口文档，再参考项目本地 `api.md` / `api-docs.md` / `api-word.md`。
   - 务必读取 `docs/README.md` 或入口文档以了解全貌。
   - 项目本地接口文档只能作为补充线索；当线上接口文档可访问时，以线上真实接口定义为准。

4. **执行任务**
   - **场景 A：回答问题**
     - 基于文档内容回答用户问题。
     - 引用文档中的具体章节作为依据。
     - 如果文档中未提及或有冲突，明确告知用户，不要编造。
   - **场景 B：生成/修改代码**
     - **严格遵循规范**：代码风格、命名、目录结构必须与 `docs` 中的规范一致。
     - **引用上下文**：在生成代码前，先简要说明依据的文档规范。
     - **实施变更**：执行具体的代码编辑操作。
   - **场景 C：接口文档查询**
     - 必须说明查询来源环境（dev / test / 用户提供链接）。
     - 按“接口名称、请求方法、接口路径、请求参数、响应字段、注意事项、待确认项”的结构输出。
     - 字段名必须与文档完全一致；文档缺失字段使用 `TODO无此联调字段_用途描述`，静态阶段未确认字段使用 `TODO待联调_用途描述`。
     - 禁止根据命名习惯猜测接口 URL、Query 参数、Body 字段或响应字段。

5. **自我检查**
   - 确认最终结果（答案或代码）是否违反了读取到的文档中的任何硬性规定。
   - 确认接口相关结论是否已经标明文档来源环境。
   - 确认没有把项目已有代码里的请求参数当作文档结论，除非文档明确一致。
