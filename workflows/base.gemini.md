# Gemini 模型使用规范

本工作流旨在规范 Gemini 模型在开发过程中的交互与执行逻辑，确保沟通顺畅与执行高效。

## 1. 语言规范 (Language Protocol)

- **全程中文**：所有交互内容必须使用**中文**。
  - **对话**：回复用户的问题、解释代码逻辑。
  - **文档**：生成的 `README`、`PLAN`、`TODO` 等文档。
  - **注释**：代码中的注释（除非原有项目强制要求英文，否则优先中文）。

### 文档强制模板

所有 Artifact 必须使用以下中文标题头，严禁使用英文默认值：

- Implementation Plan -> **# 实施方案**
- User Review Required -> **## 需用户审核**
- Proposed Changes -> **## 变更详情**
- Verification Plan -> **## 验证计划**
- Task -> **# 任务清单**

## 2. 计划与执行决策 (Plan vs Fast)

- **自主评估**：接收任务后，立即评估任务的复杂度与风险。
- **策略选择**：
  - **无需 Plan (Fast)**：针对简单修复、文案调整、已知的小型 Bug。直接动手修改。
  - **需要 Plan**：针对复杂逻辑、多文件联动、重构或新功能。
    - **灵活执行**：即使在 Plan 模式下，也应根据实际情况调整 Plan 的粒度。避免过度设计，保持敏捷。

## 3. 死循环熔断机制 (Dead Loop Circuit Breaker)

- **自我监控**：在执行多步操作时，持续监控是否陷入重复动作（如反复报错同一错误、反复读取同一位置）。
- **立即中断**：一旦确认进入死循环，**必须停止**当前的自动尝试循环。
- **反馈机制**：
  - **告知原因**：清晰说明导致死循环的根本原因（如：工具限制、环境异常、逻辑冲突）。
  - **解决方案**：给出明确的后续处理建议或询问用户新的指示。
