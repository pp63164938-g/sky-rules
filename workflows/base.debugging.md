# 联调工作流

## 1. 准备阶段

1. 优先查看当前任务相关的需求文档 / 原型 / 用户提供截图，先明确页面文案、字段标题、展示顺序、交互流程和业务语义；再查看项目根目录下的接口文档文件（优先级：`api.md` > `api-docs.md` > `api-word.md`），核对接口字段链路。
2. 如果项目本地没有接口文档，或本地文档未覆盖当前要联调的接口、字段、参数、枚举、响应结构，必须继续查询线上接口文档，禁止停在“本地没有 / 本地没写 / 文档不够”就结束判断。
   - 线上接口文档查询规则遵循 `base-docs` 工作流中的“查询线上接口文档”
   - 当前已知入口优先级：dev 文档 > test 文档
   - dev 环境：`https://gw-kunlun.tyhdev.com/doc.html#/home`
   - test 环境：`https://gw-kunlun.tyhtest.com/doc.html#/home`
   - 本地文档与线上文档不一致时，必须列出差异并询问用户以哪个来源为准，不能自行取其中一个继续改代码
3. 如果线上文档不可访问、需要登录、返回登录过期或网络受限，必须明确告知用户，并要求用户提供可访问环境、截图、接口文档内容或抓包信息
4. 如果本地文档与线上文档不一致，必须列出差异，并询问用户以哪个文档来源为准
5. 如果需求文档 / 原型 / 用户截图与接口文档在页面是否展示、字段名称、字段类型、枚举值、下拉选项、提交结构或接口范围上不一致，必须先输出差异、影响和建议处理方式，并询问用户以哪个来源或后端确认为准；禁止自行选择其中一个来源继续改代码。
6. 确认要联调的接口范围和涉及的文件

## 2. 联调执行

### 联调适配判断

- **联调不是机械替换**：删除 Mock、替换 URL、替换字段名之前，必须先判断接口契约与当前页面真实使用场景是否匹配，包括请求方式、分页结构、响应路径、字段语义、是否需要级联 / 多选 / 回显 / 删除 / 保存、列表行是否有稳定 ID、接口返回是否覆盖当前交互。
- **先判断影响再改代码**：如果接口只提供 `id/name`，但页面需要级联层级、父子关系、员工工号、禁用状态或回显字段，不能只把接口接上就算完成；必须确认缺失信息是否影响展示、查询、提交或后续交互。
- **替换后必须回看调用链**：接口函数替换后，必须沿着组件调用链检查表格列、搜索项、弹窗、formatter、删除 / 保存参数、空态和刷新逻辑，确认新接口数据结构能支撑实际页面行为。
- **接口不适配时必须显性处理**：如果接口能替换一部分，但不能满足当前业务实际场景，已确认部分正常联调；缺失部分保留可感知占位或 `TODO无此联调字段_用途描述`，并在最终回复中说明缺口、影响范围和待确认事项。
- **禁止为了完成联调伪造适配**：禁止为了让页面“看起来已联调”而用前端本地拼接、静态默认值、相似字段、列表快照、中文文案判断或相似接口补齐真实接口没有承载的能力。

### 字段映射规则

- **页面表现按需求文档**：表格列名、表单 label、按钮文案、提示文案、展示顺序和交互流程，优先按需求文档 / 原型 / 用户最新说明。
- **数据契约按接口文档**：接口字段名、请求参数名、响应路径、字段类型、枚举真实值和提交结构，必须与接口文档 / 抓包 / 后端确认一致。
- **接口说明不覆盖页面文案**：接口字段说明只能辅助理解字段含义，不能直接覆盖需求文档中的页面文案；例如接口字段说明为“备注”，但需求图写“等级说明”，页面 label 使用“等级说明”，代码绑定仍使用接口字段名。
- **文档缺失字段**：使用 `TODO无此联调字段_字段名` 标记占位，禁止自行发散生成
- **待确认字段**：保留静态开发时的 `TODO待联调_` 前缀，联调时替换为真实字段名
- **联调阶段禁止遗留 `TODO待联调_`**：`TODO待联调_` 只表示静态开发阶段的待确认占位。进入联调后，当前联调范围内所有 `TODO待联调_` 必须逐项处理：接口文档、抓包或后端已提供真实字段 / 参数 / 枚举值时，必须替换为真实名称；仍未提供但业务需要时，必须改为 `TODO无此联调字段_用途描述` 并在最终回复中列为待确认项。禁止把 `TODO待联调_` 原样保留到联调交付结果中。
- **联调确认后清理临时命名**：静态开发 / 未联调阶段允许使用 `form_`、`table_`、`mock`、`temp`、`TODO待联调_` 等临时命名预留；进入联调后，接口字段、枚举、Options、Dispatch、表单项等已经确认时，必须替换为真实接口字段名或接口字段链路命名，例如 `statusOptions`、`templateIdOptions`。
- **分层原则不等于自动解决冲突**：页面文案与接口字段名这类差异可以按“表现归需求、契约归接口”分层处理；但同一位置出现互斥结论时，必须先沟通确认，不能把冲突静默消化成实现细节。
- **静态预留内容是联调依据**：如果当前页面已有根据需求文档、原型、截图或用户确认预留的入口、字段、下拉、列、按钮、弹窗区域、API mock 或 `TODO待联调_`，联调时发现后端接口缺失或对不上，禁止直接删除预留内容。必须先说明预留依据、接口缺口和影响范围；已确认需求范围内的预留应保留可感知入口，并将未确认字段改为 `TODO无此联调字段_用途描述`。
- **缺失数据源不得硬凑**：下拉、弹窗、筛选项、详情模块等没有对应接口文档、抓包、后端确认或项目真实接口时，禁止拿相似页面、分页接口、列表接口或名称相近接口硬凑成确定功能。
- **缺失接口时保留用户可感知入口**：需求明确存在的页面入口、搜索项、按钮、页签、表格列、弹窗区域，在接口未提供或未联调确认时，禁止直接删除；应保留禁用态、空状态、提示文案、tips 或占位组件，并用 `TODO无此联调字段_用途描述` 标记。

### Mock 数据清理

- 删除 `// @mock-start 联调时删除` 到 `// @mock-end` 之间的代码块（包括标记）
- 取消注释正式请求代码

## 3. 问题处理原则

> [!CAUTION]
> **绝对禁止自行发散生成不存在的字段！** 问题会隐藏太深，难以发现。

遇到以下情况必须及时沟通：
- 接口文档缺少某个字段
- 字段类型或格式与预期不符
- 接口返回结构与文档不一致
- 需求文档 / 原型 / 用户截图与接口文档不一致
- 本地接口文档、线上接口文档、抓包或测试环境返回不一致
- 静态开发阶段已按需求预留的内容，联调时发现后端接口缺失、类型不符、结构不一致或数据源不可用
- 任何不确定的地方

### 不确定信息处理

联调中凡是接口文档、测试环境返回、用户截图或已有代码无法确认的字段、参数、交互能力，必须先反馈给用户并确认方案，禁止为了推进任务自行硬加字段、硬改组件能力或把单选改多选。

❌ 错误做法：

- 文档只有 `performanceType: integer`，但根据截图直接改成多选数组
- 文档没有周期 ROI 字段，直接按命名习惯写 `m0m1Roi`
- 不确定字段含义时，用相近字段替代展示

✅ 正确做法：

- 明确说明“文档未提供该字段 / 类型 / 能力”
- 使用 `TODO无此联调字段_用途描述` 标记缺失字段
- 将待确认接口、字段、页面位置整理给用户，由用户确认后端补字段或调整交互方案后再改代码
- 如果需求入口已经存在但接口未提供，保留用户可感知占位，禁止只在代码注释中说明缺口
- 如果数据源未确认，禁止用分页接口、列表接口或相似页面接口包装成下拉 Options

## 4. 联调检查清单

- [ ] 已确认本次替换的接口契约能支撑当前页面真实使用场景，不只是替换 URL / 字段名
- [ ] 已沿调用链复查搜索、表格、弹窗、formatter、保存 / 删除参数和刷新逻辑是否与接口结构匹配
- [ ] 当前联调范围内已搜索 `TODO待联调_`，相关项已替换为真实字段 / 参数 / 枚举值，或改为 `TODO无此联调字段_` 并记录待确认
- [ ] 当前联调范围内已搜索 `form_`、`table_`、`mock`、`temp`、`待联调` 等临时命名，已确认内容改为真实接口字段名或接口字段链路命名，未确认内容保留可搜索 TODO 标记
- [ ] 当前页面所有需求入口未因缺接口被静默删除；缺接口时已保留用户可感知占位
- [ ] 当前页面所有下拉 / 远程搜索数据源均有接口文档、抓包、后端确认或项目真实接口依据；没有依据的未硬凑，已标记并反馈
- [ ] 最终回复已列出所有临时占位和待提供接口，不要求用户从代码注释里反查
- [ ] 所有 `@mock-start/@mock-end` 代码块已清理
- [ ] 缺失字段已用 `TODO无此联调字段_` 标记并记录
- [ ] 接口响应结构与文档一致

## 5. 接口梳理

联调完成后，梳理接口使用情况：

### 输出格式

```markdown
## 接口使用情况

### 已使用接口
| 接口名称 | 文件位置 | 用途 |
|---------|---------|-----|
| getUserInfo | src/api/user.js | 获取用户信息 |

### 未使用接口
| 接口名称 | 文档位置 | 建议 |
|---------|---------|-----|
| getOldUserList | api.md 第 45 行 | 确认是否需要 / 可删除 |

### 待确认项
- `TODO无此联调字段_xxx` - 需要与后端确认
```

### 梳理步骤

1. 对比本地接口文档或线上接口文档中的接口列表
2. 检查代码中实际调用的接口
3. 列出文档有但代码未使用的接口
4. 标注每个未使用接口的处理建议
