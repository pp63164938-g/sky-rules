# 修复 Bug 工作流

适用场景：用户提供 PingCode 工单截图，根据截图中的信息定位并修复代码问题。

## 0. 显式触发约束

- 仅当用户显式调用 `$base-pingcode-fix-bug`，或明确要求“使用截图 Bug 修复工作流”时执行。
- 用户仅提供页面截图、Bug 截图、工单截图，或要求修复页面、样式、代码问题，不构成触发条件；按当前任务适用的普通规则处理。

## 步骤

### 1. 解析截图信息

从截图中提取以下关键信息：

- **问题概述**：Bug 的描述
- **文件路径**：问题代码所在文件
- **行号范围**：问题代码的行号
- **问题代码**：当前有问题的代码片段
- **修复建议**：截图中给出的修复方向（仅做参考）

### 2. 查看实际代码

// turbo
根据截图中的文件路径和行号，使用 `view_file` 查看实际代码，确认：

- 代码是否与截图一致（可能已被其他人修改）
- 问题是否确实存在
- 影响范围有多大

### 3. 评估并等待用户确认

> **⚠️ 禁止直接修改代码，必须等待用户明确确认后才可修复。**

向用户简要说明：

- **风险等级**：是否会导致线上崩溃/白屏/数据错误，还是仅影响边界场景
- **修复成本**：改动量大小
- **建议**：是否值得修复

**然后停下来，等待用户回复确认是否修复。**

### 4. 修复代码（用户确认后）

收到用户确认后，进行代码修复。修复时注意：

- 截图中的推荐方案**仅供参考**，核心目标是解决问题本身
- 如果有更优的修复方案（更简洁、更符合项目规范），则采用我们自己的方案
- 遵循项目已有的代码风格和规范
- 不要过度修改，只修复问题本身

### 5. 反馈结果

向用户说明修改了什么、为什么这样改。
