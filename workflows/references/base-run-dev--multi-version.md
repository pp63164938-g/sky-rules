# 多版本本地联调启动

仅在用户已经确认本次按多版本本地联调启动时读取。普通本地启动不读取本文件。版本标识和字段口径以 `rules/enterprise/sky/backend/50-multi-version-local-debug.md` 为准，本文件只写启动顺序。

## 1. 启动前

1. 先区分前端、本次要启动的后端实例、只提供类的依赖包。依赖包不单独启动。
2. 从当前开发分支确认版本标识。已确认格式 `feature/vX.Y.Z` 转为 `feature-vX-Y-Z`，`/` 和 `.` 换成 `-`。不符合该格式时先问，不猜测。
3. 从当前项目配置读取启动类、端口、JDK 和本地地址。禁止沿用其他项目或其他演示里的地址和端口。
4. 动手前说明：哪些实例带版本标识启动，哪些不启动，前端准备用哪个入口连接。

## 2. 启动

1. 后端只追加四个环境变量：`DEPLOY_TIME`、`DEPLOY_ENV`、`DEPLOY_TYPE=gray`、`DEPLOY_VERSION=<已确认版本标识>`。
2. `DEPLOY_TIME` 使用本次启动时间，`DEPLOY_ENV` 使用当前目标环境。不要把这两个值改成版本标识。
3. 环境变量加在本次启动命令或 IDE 启动配置中。禁止为了加环境变量修改业务源码或默认配置文件。
4. 前端不改请求工具。通过带 `gray=<已确认版本标识>` 的入口访问，或只在本次浏览器写入同名本地值。请求拦截器会把它带到 `X-Deploy-Version`。
5. 域名自动进入的 `latest` 不是本次迭代标识。本次联调必须显式使用已确认版本标识。

## 3. 验收

1. 后端进程环境中的 `DEPLOY_VERSION`、前端本地 `gray` 和请求头 `X-Deploy-Version` 三者一致。
2. 请求打到本次启动的本地实例，而不是等待共享环境构建结果。
3. 地址、端口或透传字段和当前源码不一致时，先说明差异，不另写一套兼容字段。

## 4. 运行产物

本次追加的环境变量、IDE 启动参数、临时代理和浏览器本地版本值，都列入「本地运行产物」，默认不提交。清空浏览器中的版本值，只影响本次浏览器，不改变后端实例。
