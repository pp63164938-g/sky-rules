# 本地启动经验

只记录已验证、可跨项目复用的启动问题。使用前必须重新核对当前项目的端口、JDK 和依赖版本。

## IDE 编译产物互相覆盖

- 信号：一个 IDE 修好的 class，被另一个 IDE 的重新构建删除或覆盖。
- 处理：同一模块只留一个 IDE 编译和启动。
- 失效：两个 IDE 输出目录不同，且启动 classpath 明确分离。

## 缺类但补丁 jar 仍不注册

- 信号：类能加载，框架仍报缺少对应 Bean。
- 处理：不要只在 classpath 前追加零散 class。把缺失类合并进原依赖 jar 的副本，再用副本替换原依赖。
- 失效：框架按组件索引而不是包扫描注册，合并 jar 后仍要更新索引。

## 命令行过长

- 信号：构建成功后，启动失败并提示命令行过长。
- 处理：启动配置改为把 classpath 写入参数文件，再重新启动。

## Java 17 反射被模块拦住

- 信号：`InaccessibleObjectException`，栈里有旧字节码库调用 `ClassLoader.defineClass`。
- 处理：沿用项目已有启动参数，补上对应 `--add-opens`。不要升级业务依赖来绕过，除非项目已经要求升级。
