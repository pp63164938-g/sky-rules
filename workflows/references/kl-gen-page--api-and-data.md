# Kunlun API 与数据契约实现细则

## 字段、Options 与枚举

- 已确认的表单字段、查询参数和表格列直接使用目标接口字段名，`prop`、`v-model` 和请求字段保持一致；禁止机械增加 `form_`、`table_` 或二次映射名称。
- 未确认契约在最终使用位置使用 `TODO待联调_用途描述`；进入联调后接口仍缺失时改为 `TODO无此联调字段_用途描述`。禁止同时维护临时字段与正式字段两套状态。
- 需求入口明确但接口缺失时保留真实控件、交互和目标 API 调用位置；静态成功只放 API 层 Mock，禁止删除入口、禁用功能或借用相似接口。
- 下拉 Options 按接口字段链路命名，例如 `statusOptions`、`templateIdOptions`；缺少数据源时不使用分页接口或相似页面接口包装 Options。
- 标准 `id/name` 响应优先使用当前项目 `@/components/common/form/utils` 中的 `getIdName2ValueLabelList`；标准 `{ label, value }` Options 取项使用同位置的 `getListOption`，普通文本标签使用 `getListOptionLabel`。使用前重新读取工具函数源码和类型。
- 标准静态 Options 显式声明 `CommonEnum`，远程下拉为 `useSimpleSelecter` 提供与真实响应一致的泛型；枚举、常量和 TODO 值继续执行全局“枚举映射规范”和“函数抽象边界规范”，本引用不维护第二套口径。

## 权限、唯一标识与主键

- 权限标识必须来自菜单管理、接口文档、后端、用户确认或项目已有同功能真实代码。未确认时只使用项目约定的 `v-sky-authorize="'TODO：功能权限待配置'"` 占位，禁止按路由或操作名拼接其他权限字符串。
- `useCustomizeField` 的唯一标识、表格主键、删除参数和编辑标识必须分别确认真实来源；字段名称看起来唯一不能作为依据。
- 当前项目对开发环境权限占位的放行策略属于可变化事实。使用占位前必须查看当前权限钩子；策略不存在或变化时停止套用旧结论并反馈。

## 静态 Mock 与正式请求

- Mock 只能位于 API 函数内部，使用 `// @mock-start 联调时删除` 与 `// @mock-end` 最小包裹；组件始终调用正式 API 函数。
- Mock 只提供支撑页面展示和列宽验证所需的少量记录，不模拟筛选、分页、排序和业务判断。
- `@mock-end` 后保留被注释的正式请求及真实入参位置；联调时删除 Mock 块并按接口文档启用正式请求。
- 禁止在 `useTable.fnApi`、组件事件或页面状态中使用 `Promise.resolve`、`as any` 或本地数据伪造后端成功。

## API 文件与类型位置

- 新增接口前搜索整个 `src/api`，优先追加到当前业务域已有 API 文件；只有全新独立业务域或用户明确要求时才新建文件。
- 请求异常提示沿用当前模块已经验证的 Kunlun 请求配置。若项目仍使用统一 `message` 常量，则在 API 文件头统一声明并在请求配置中复用；当前模块源码不一致时不得强行套用旧写法。
- 请求入参、响应类型、`Omix` 边界和跨接口字段归属执行全局 API 类型规则。已确认响应禁止使用 `request<Omix>` 或 `request<Array<Omix>>`。
- 当前项目确实使用 `src/api/{module}/interface/{domain}.resolver.ts` 和统一出口时，复杂或外部消费 DTO 沿用该结构并补齐导出链；项目结构变化时先以全项目真实类型出口为准。
- API 实现文件只保留请求函数、必要导入、请求配置和函数内部 Mock；普通业务 URL 在函数定义处直接写完整路径，不抽局部前缀常量。
- 接口路径、方法、Query、Body、响应路径、字段类型和枚举值只能来自当前目标接口，禁止跨接口借字段或猜测导入路径。
