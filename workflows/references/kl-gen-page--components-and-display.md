# Kunlun 组件与展示实现细则

## 项目组件事实查证

- 使用 `com-*`、`sky-*`、`business-*`、Hook 或工具函数前，读取当前源码、类型定义或项目文档，确认 Props、默认值、合法值、返回结构和副作用。
- 引用资料中的组件路径和默认值只用于定位，不替代当前源码。源码不存在、类型不匹配或行为已变化时，停止套用对应条目并反馈规则失效。
- 模板已有且符合需求的 Props 保留；需求明确需要的 Props 才补充；组件默认值已满足需求时不重复传参，也不为了“保险”传 `false`、空值或默认配置。
- 公共组件无法覆盖需求时，先说明已查证的能力边界，再使用局部实现；禁止只参考其他页面照抄参数。

## Element Plus namespace

- 当前 Kunlun 项目的 Element Plus 运行时 namespace 为 `el-sky`：DOM 类名使用 `.el-sky-*`，CSS 变量使用 `--el-sky-*`。
- Vue 组件标签 `<el-button>`、`<el-select>` 等不属于运行时类名，继续按项目注册方式使用。
- 使用 namespace 前以当前项目配置、组件源码或实际 DOM 为准；配置变化时更新项目规则，禁止同时保留默认 `.el-*` / `--el-*` 作为无依据兼容。

## 枚举标签与下拉展示

- 枚举值映射为标签文案或颜色时优先使用 `com-map-tag`，并把 label、value、type/color 等配置集中在 Options / TagMap。
- 统一展示属性写在 `com-map-tag` Props 上；只有单个枚举项具有特殊表现时，才把该属性放进对应配置项。
- 普通文本枚举展示使用 `getListOptionLabel`；需要读取选项额外字段时使用 `getListOption`。标签展示和表单控件分别使用展示组件与 `com-form-*`，禁止混用职责。
- 简单表格标签由 `formatterRender` 返回 `com-map-tag`；只有包含复杂交互或多区块结构时才使用列插槽。

## 长文本与空值

- 卡片、详情、弹窗只读区、下拉选项和自定义列中长度不确定的接口文本，优先使用 `sky-ellipsis-tooltip`；单行默认省略，需求明确多行摘要时设置 `line-clamp`。
- 普通表格文本列已经由组件处理溢出时不重复包裹；静态短文案、按钮文案和已有明确截断能力的组件也不机械增加 Tooltip。
- 当前项目纯文本空值展示优先使用 `@/utils/utils-common` 的 `formatEmptyValue`；业务空值判断使用同方向的 `isBlank` / `isNotBlank`。使用前确认当前实现仍保留 `0`、`false` 等有效值。
- `formatEmptyValue` 只用于展示，不参与表单初始化、查询参数、提交或业务分支；普通表格列已有统一空值处理时不重复格式化。
- 禁止在业务页面重复声明 `formatText`、`formatEmptyText` 或使用 `value || '-'` 掩盖有效的 `0`、`false`。

## 样式与默认视觉

- 优先使用组件 Props、默认样式和项目公共变量。只有明确设计或业务差异无法由组件能力表达时，才增加局部样式。
- 新增 SCSS 按模板 DOM 父子关系组织完整选择器路径，遵循全局 CSS/SCSS 规范和 Kunlun namespace 检查；禁止把项目专属状态写入通用组件。
- 交付前检查本次修改文件中的默认 `.el-*` / `--el-*`、无依据硬编码变量、重复组件默认样式和未说明的长文本兜底。
