# Kunlun 表单与弹窗实现细则

## 标准弹窗骨架

- 标准业务弹窗放在当前页面的 `dialog/` 目录，禁止直接内联到列表页 `index.vue`。
- 列表页通过 `createDefaultComponent` 动态加载弹窗，只负责传入模式、稳定标识和提交成功后的刷新；弹窗负责回显、校验、提交、成功提示和关闭。
- 弹窗内部以 `src/components/dev-template/dialog/dialog-update.vue` 为唯一骨架来源，按当前源码保留 `sky-dialog`、`dialogValue`、loading 拆分、`useForm`、`handleConfirm` 和 `emit('submit')` 等职责。
- 编辑入口默认只传已确认的稳定标识，弹窗内部调用详情接口回显；列表行不作为编辑表单数据源。只有需求明确列表数据就是完整编辑数据时才允许传行对象，并在交付中说明依据。
- 后端尚未提供详情接口时，在 API 层预留详情函数和 Mock，弹窗继续走正式调用链；禁止在组件中复制列表快照伪造详情结果。

## 表单布局、校验与组件默认值

- 标准新增 / 编辑弹窗使用模板的双列 `common-grid-form`。普通输入、选择、开关和只读字段默认占一列；长文本、备注、附件或复杂业务块确需横向空间时才使用 `col-span-full`。
- 除非设计或需求明确要求，不覆盖 `sky-dialog` 的模板默认宽度。
- `com-form-*` 已能通过 `required` 生成普通必填校验时，不在 `useForm` 中重复声明同字段规则；复杂校验、跨字段校验或自定义 validator 才进入 `formRules`。
- 使用 `required`、`maxlength`、`clearable`、`autosize` 等 Props 前读取组件源码。需求与默认值一致时不重复传参；默认值变化时以当前源码为准并反馈引用资料失效。
- 标准弹窗使用 `useForm({...})` 的真实字段结构进行类型推断。复杂模型可以使用明确业务类型，禁止用 `Omix`、`any` 或无依据断言绕过类型问题。

## 上传与交互提示

- 标准表单上传先检查并复用 `com-form-upload`，使用其已提供的 token、文件类型、大小、数量限制和成功提示能力；禁止重复手写公共校验。
- 上传接口必须来自接口文档、抓包或后端确认。接口未提供时保持正式上传组件和交互，在最终 `url` 绑定位置使用 `TODO待联调_附件上传接口`，禁止伪造地址或改成本地流程。
- 按钮禁用态、显隐或组件校验已经阻止普通前置条件时，业务函数不重复提示“请选择”或“请填写”；函数只处理真实业务异常和接口异常。
- 操作按钮内部需要业务提示时，按当前组件契约使用 `com-tips-wrapper` 的 inline 模式；提示内容只说明业务原因、风险或影响。

## 组件拆分与目录化

- 标准列表的搜索区、表格区、header/tool 插槽，以及标准弹窗的普通表单区保持在模板主文件中；禁止只为减少行数拆组件。
- 动态表格、复杂配置、独立校验、选择器或可复用业务块具备清晰职责时，才拆成页面专属组件；子组件负责局部状态和校验，父组件负责主提交和刷新。
- 简单弹窗保持 `dialog/dialog-业务名.vue`。只有必须抽离至少一个专属组件、类型、Hook 或函数文件时，才升级为 `dialogs/dialog-业务名/index.vue` 目录结构。
- 复杂弹窗目录下的组件使用真实业务名称，禁止使用 `table.vue`、`panel.vue`、`config.vue` 等含糊命名，也禁止在 `src/components/dev-template/dialogs/` 中开发真实业务弹窗。
