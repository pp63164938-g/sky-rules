# Figma 设计稿转代码工作流

适用场景：用户提供 Figma 设计截图和/或从 Figma 复制的样式参数，需要完成 UI 样式开发或改造。

## 核心原则：图文结合，智能映射

**Figma 导出的参数仅作为参考，不可机械复制。** 必须结合截图的视觉效果，将 Figma 参数智能映射为正确的 CSS 属性。

### Figma 参数 → CSS 属性映射规则

Figma 的属性命名与 CSS 不完全一致，常见映射：

| Figma 参数 | 实际 CSS 含义（需结合上下文判断） |
|---|---|
| `background` 用在文字上 | → `color`（文字颜色，不是背景色） |
| `background` 用在容器上 | → `background` / `background-color` |
| `leading-trim: NONE` | → 忽略，CSS 无此属性 |
| `font-style: 55 Regular` | → `font-weight: 400`（Figma 的字重描述） |
| `font-style: 65 Medium` | → `font-weight: 500` |
| `font-style: 75 SemiBold` | → `font-weight: 600` |
| `font-style: 85 Bold` | → `font-weight: 700` |
| `letter-spacing: 0%` | → 忽略或 `letter-spacing: 0` |
| `opacity: 1` | → 忽略（默认值） |
| `angle: 0 deg` | → 忽略（无旋转） |
| `width` / `height` 无单位 | → 加 `px` 单位 |
| `border: Mixed solid` | → 需看子元素各边框分别定义 |
| `font-family: Alibaba PuHuiTi 2.0` | → 检查项目是否已引入该字体，未引入则忽略 |

### Figma 字重编号速查

| Figma font-style 编号 | CSS font-weight |
|---|---|
| 25 Thin | 100 |
| 35 Light | 300 |
| 45 Regular / 55 Regular | 400 |
| 65 Medium | 500 |
| 75 SemiBold | 600 |
| 85 Bold | 700 |
| 95 Black | 900 |

## 🚨 绝对红线：严禁 AI 推导注释

在进行 Figma 到 CSS 的转化时，**绝对禁止**在生成的代码中留下任何暴露 AI 思考过程或解释 Figma 对应关系的冗余注释。代码注释必须仅对业务负责，保持纯净。

- ❌ **禁止来源标记**：严禁说明参数出处，如 `/* 匹配 Figma 18px */`、`/* 根据设计图推导 */`。
- ❌ **禁止推导解释**：严禁记录 AI 的内心活动，如 `/* 因为容器没有 padding，由单项提供 */`、`/* 满足全宽背景需求 */`。
- ✅ **必须保留核心业务注释**：必须为各个样式块补充简明扼要的**业务功能说明**（如 `/* 进度条轨道底色 */`、`/* 累计总消费量标签文字 */`）。代码注释应标明它是“什么模块”，而不是“为什么这么写”。

## 工作流步骤

### 1. 分析设计意图

**截图优先**：先看截图理解整体布局、层级关系、视觉效果：
- 元素的排列方向（横/纵）
- 层级嵌套关系（谁包含谁）
- 间距和对齐方式
- 颜色用途（背景色 vs 文字色 vs 边框色）
- 交互状态（hover、active、disabled）

### 2. 智能解析 Figma 参数

对用户提供的每组参数：
1. **判断元素类型**：是容器、文字、图标、按钮？
2. **映射属性**：根据元素类型将 Figma 参数映射为正确的 CSS
3. **过滤噪音**：忽略默认值和 CSS 不支持的属性
4. **补充遗漏**：截图中可见但参数中未提及的样式（如 `cursor: pointer`、`display: flex`）

**关键判断逻辑**：
```
如果 Figma 参数 `background: #333` 出现在文字描述中：
  → 实际应该是 `color: #333`

如果 Figma 参数 `background: #FFEBF6` 出现在容器/按钮描述中：
  → 实际就是 `background: #FFEBF6`
```

### 3. 对比现有代码

- 查看目标文件的当前样式
- 识别哪些需要修改、哪些需要新增
- 遵循项目现有的 CSS 规范（BEM、嵌套规则等）

### 4. 实施修改

- 只改用户指定的部分，不发散
- 保持与项目现有风格一致
- 遵循用户全局规则中的 CSS/SCSS 样式规范

### 5. 资源处理规范 (SVG / 图片)

- **主动寻找素材**：开发中如需用到 SVG 或图片资源，优先在项目根目录（或根目录的临时文件夹，如 `svg/`、`images/` 等）寻找用户提供的原始素材。
- **智能重命名与归位**：用户提供的素材通常仅作源文件参考。你需要根据其业务语义自行**重命名**，并将其**移动到系统标准资源目录**（例如 `src/icons/svg/` 或 `src/assets/images/`），绝不可将临时目录的路径直接硬编码到业务代码中。
- **遵循系统加载规范**：必须参考并复用当前项目已有的 SVG/图片 使用规范（例如，若系统统一使用 `<svg-icon icon-class="...">` 处理 SVG，绝不可使用 `<img>` 强行引入）。
- **TODO 缺省占位**：如果设计稿（Figma）中存在图片/图标，但用户**未提供**相应的素材文件，**必须**在对应位置预留好 DOM 结构，并使用带中文语境的 `TODO` 标记（例如 `TODOicon_待替换的首页图标`、`<!-- TODO图片_活动背景大图占位 -->`）进行注释和类名占位，方便后期统一搜索替换。
- **SVG / Icon 尺寸调整规范**：不同的系统对 Icon 的底层实现方式不同（例如有些基于 `1em` 继承 `font-size` 进行缩放，有些则基于精确的 `width` / `height` 控制）。在需要调整图标尺寸时，**绝对禁止无根据地猜测或盲目设置外层容器的宽高**。必须先主动查阅当前项目中该图标组件的底层实现方式，明确它是受 `font-size` 还是受 `width`/`height` 影响后，再对症下药应用对应的 CSS 属性。

### 6. 确认输出

修改完成后，简要说明：
- 改了什么（用表格对比新旧值）
- 如有 Figma 参数被智能映射（如 background → color），主动说明

## 常见陷阱提醒

### 间距与坐标的精准推导 (Figma Inspect)

在观察 Figma 截图中的红线标注（如 130、187 等数字）时，必须极其谨慎地进行数学推导，**绝不可直接盲目照抄**为 `gap` 或 `margin`：

1. **区分「容器内边距」与「元素间距」**：
   - 如果红线是从元素边缘连接到其**父容器的外边缘**，这通常代表父容器的 `padding`（例如红线标注 `130` 到屏幕最左侧）。
   - 如果红线是连接**两个相邻元素**，这才是真正的 `gap`。
2. **高度警惕「跨元素」的长距离绝对标注**：
   - 有时 Figma 的红线会越过相邻元素，直接指向整个屏幕或容器的最边缘（例如标注为 `187` 到右边缘）。
   - 这种情况下，**绝对不能**直接将其写成两个元素间的 `gap`！必须通过减法计算求得真实的相对间距：
     `实际 Gap = 总距离标注 - 途中元素的宽度 - 容器末端内边距`
3. **结合绝对坐标 (X/Y) 进行边界验证**：
   - 遇到复杂布局时，不要主观臆断对称布局（如误认为左右 padding 都是 130px）。应通过 Figma 右侧面板的 `X` 坐标、元素 `W` 宽度，结合画板总宽（如 1440），推算出真实的右侧 Padding。
   - 推导公式：`真实 Right Padding = 总宽 - (最右侧元素的 X 坐标 + 元素的宽度)`。

### 其他常见陷阱

1. **Figma 的 `background` 不一定是 CSS 的 `background`**：文字元素的 `background` 实际是 `color`
2. **Figma 的尺寸无单位**：`width: 64` → `width: 64px`
3. **Figma 的 `border: Mixed solid`**：表示各边框不一致，需要看具体子属性
4. **Figma 的 `font-style`**：不是 CSS 的 italic/normal，而是字重描述
5. **不要盲目设置 `font-family`**：先确认项目是否引入了该字体
6. **`leading-trim`、`angle` 等属性**：CSS 不支持或无意义，直接忽略
7. **同一个颜色值在不同上下文含义不同**：同样是 `#8B9099`，用在文字上是 `color`，用在容器上可能是 `background`
