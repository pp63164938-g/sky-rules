# UI 对比工作流

## 使用方式

用户提供两张图片：
1. **第一张（或前几张）**：UI 设计稿
2. **最后一张**：实际实现效果截图

## 对比流程

### 1. 差异分析

逐项对比以下维度：

| 维度 | 检查项 |
|-----|-------|
| 布局 | 间距、对齐、排列方向、flex 属性 |
| 尺寸 | 宽高、min/max 限制、比例 |
| 颜色 | 背景色、文字色、边框色、渐变 |
| 字体 | 字号、字重、行高、字体族 |
| 边框 | 粗细、样式、圆角 |
| 阴影 | 投影效果 |
| 图标 | 大小、颜色、位置 |
| 状态 | hover、active、disabled 效果 |

### 2. 输出格式

```markdown
## UI 差异分析

### 差异项

| 序号 | 元素 | 问题描述 | 设计值 | 当前值 |
|-----|-----|---------|-------|-------|
| 1 | 标题文字 | 字号偏小 | 18px | 14px |
| 2 | 按钮 | 圆角不一致 | 8px | 4px |
| 3 | 卡片间距 | 间距过大 | 12px | 20px |

### 修复建议

按优先级排序，从上到下依次修复。
```

### 3. 矫正执行

1. 确认需要修复的文件路径
2. 逐项修复差异
3. 每项修复后说明改动内容
4. 全部修复后建议用户刷新页面验证

## 注意事项

- 如果设计稿不清晰，先询问具体数值
- 修复时优先使用项目已有的设计变量（如 CSS 变量、SCSS 变量）
- 复杂动效差异需单独沟通确认

## 文案内容禁止自行发散

**核心原则**：**严禁在 UI 对比流程中，从设计截图自行读取并生成文案内容**。UI 对比的设计稿仅用于对比样式和布局。

**区分两种场景**：

| 场景 | 是否可用 | 说明 |
|------|---------|------|
| UI 对比的设计截图 | ❌ 禁止读取文案 | 设计稿仅用于样式对比，文案差异需列出让用户确认 |
| 用户明确提供的映射参考 | ✅ 可直接使用 | 用户主动提供的文案映射关系，属于用户输入 |

**禁止行为**：

- UI 对比时从设计截图中识别文字并直接写入 i18n 或代码
- 自行推测/补全用户未提供的描述文案、按钮文案

**正确做法**：

1. **已有文案**：保持不变，不做修改
2. **用户提供映射**：用户明确提供的映射关系图/文案，直接使用
3. **新增映射无来源**：文案使用 `TODO待联调_用途描述` 占位
4. **发现差异**：如果设计截图中的文案与代码不一致，**列出差异告知用户**，由用户决定是否修改


## 忽略项

以下内容在对比时**不需要关注**，是预留占位：

- `TODO翻译_xxx` - 待翻译文本
- `TODO待联调_xxx` - 待联调字段
- `TODO无此联调字段_xxx` - 待确认字段
- `TODOicon_xxx` - 待替换图标
- 任何 `TODO` 前缀的占位内容

只关注**样式和布局**差异，文本内容的 TODO 占位不影响 UI 对比。

## i18n 规范提醒

UI 对比修复涉及新增或修改 i18n 翻译时，**必须遵循以下规则**：

1. **先查看 i18n 入口文件**：确认项目的 locale 对应的实际字符集（简体/繁体），禁止凭其他项目经验套用
2. **禁止自动生成翻译**：新增的翻译 key，英文文件必须使用 `TODO翻译_中文原文` 占位，禁止自行编写英文翻译
3. **只改样式，不改翻译内容**：UI 对比的目标是修正样式差异，已有的翻译文本不在修改范围内

## Icon 预留规范

UI 对比修复涉及新增或修改 Icon 时，**必须遵循 `base.icon-replace` 工作流的预留规范**：

### 区分 Icon 来源

修复前必须先确认 icon 来源，在差异分析中标注：

| 来源 | 说明 | 处理方式 |
|------|------|----------|
| 项目已有 | `src/icons/svg/` 中已存在的 icon | 直接使用，无需标记 |
| 新增预留 | 项目中不存在，需要设计提供 | 必须附加 `TODOicon_` 标记 |

### 新增 Icon 规则

1. **必须附加 `TODOicon_` 标记**：新增的 icon 在 class 上附加 `TODOicon_用途描述`，便于后续全局搜索替换
2. **使用临时 icon 占位**：可用项目中已有的近似 icon 或 Element UI 的 icon 临时占位
3. **icon-class 命名**：参考项目已有 icon 的命名风格（如 `组件名_描述`），先查看 `src/icons/svg/` 目录
4. **差异分析中说明**：输出差异表时，新增的 icon 必须在备注中标注"需设计提供"

### 代码示例

```html
<!-- ✅ 新增 icon - 附加 TODOicon_ 标记 -->
<svg-icon icon-class="PromotionSteps_register" class="TODOicon_注册步骤图标" />

<!-- ✅ 已有 icon - 直接使用，无标记 -->
<svg-icon icon-class="PromotionSteps_success" />
```
